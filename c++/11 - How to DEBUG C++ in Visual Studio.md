这是 The Cherno《How to DEBUG C++ in Visual Studio》的笔记整理。这一集的核心观点是：调试的两大支柱是**断点**与**内存查看**，而 Visual Studio 提供了一套完整的工具链来支撑这两件事。

### 前提：必须在 Debug 模式下调试

Release 模式开启了编译器优化，代码行可能被合并、重排甚至消除，导致断点无法准确命中或变量值“对不上”。因此，所有调试操作都应在 **Debug 配置**下进行。

### 断点：控制程序停在哪里

断点的作用是让程序执行到指定行时暂停，以便你检查当时的程序状态。在 VS 中，点击代码行左侧的灰色边栏即可设置断点，或选中行后按 `F9`。按 `F5` 进入调试模式，程序会运行到第一个断点处停下。

注意：**在空行上打断点是无效的**，必须打在含有实际代码的行上。黄色箭头指向的那一行是**尚未执行**的代码，不是已经执行过的。

### 三个步进快捷键：控制如何走

断点停下后，用以下快捷键控制后续执行：

*   **F10（Step Over / 逐过程）**：执行当前行，然后停在下一行。如果当前行是一个函数调用，**不会进入函数内部**，而是把整个函数当作一步执行完。
*   **F11（Step Into / 逐语句）**：如果当前行是函数调用，按下 `F11` 会**进入该函数内部**，停在函数体的第一行。这是深入排查函数内部逻辑的关键。
*   **Shift + F11（Step Out / 跳出）**：如果你在某个函数内部，不想继续逐行看完，按 `Shift + F11` 会直接执行完当前函数的剩余部分，并返回到调用它的位置。

### 查看变量：三个窗口的分工

调试时，VS 底部通常有几个窗口自动出现，用于观察变量状态：

*   **自动窗口 (Autos)**：自动显示当前行及附近代码涉及的变量，适合快速一瞥。
*   **局部变量 (Locals)**：显示当前作用域内的所有局部变量。
*   **监视 1 (Watch 1)**：手动输入你想观察的变量名，适合持续跟踪特定变量。

### 查看内存：理解“内存就是一切”

Cherno 强调“内存就是一切”，变量窗口看到的只是解释后的值，而内存窗口展示的是原始的二进制/十六进制数据。打开方式：`调试` → `窗口` → `内存` → `内存 1`。

在内存窗口中输入 `&变量名`（例如 `&a`）即可查看该变量地址处的原始字节。一个未初始化的局部 `int` 变量，在 Debug 模式下常显示为 `cc`（十六进制），这是 VS 用来填充未初始化栈内存的标记值。执行赋值语句后，对应字节会变为实际值（例如 `a = 8` 后变为 `08 00 00 00`）。

注意：查看内存窗口时，平台需为 **x86**，否则某些填充值（如 `cc`）可能不出现。

### 关键要点总结

*   **Debug 模式是前提**：Release 优化会让调试信息失真。
*   **断点打在代码行上**，空行无效。
*   **F10 不进去，F11 进去，Shift+F11 跳出来**。
*   变量窗口看“解释后的值”，**内存窗口看原始字节**。
*   未初始化的栈变量在 Debug 下常显示 `cc`，赋值后才会变成实际数据。
