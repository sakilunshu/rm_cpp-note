这是 The Cherno《How the C++ Linker Works》的笔记整理，重点涵盖链接器的作用、常见链接错误及其解决方法。

### 核心概念：编译 vs. 链接

C++ 从源码到可执行文件分为两个主要阶段：**编译**与**链接**。

- **编译**：将每个 `.cpp` 源文件单独翻译成机器码，生成目标文件（`.obj` 或 `.o`）。此阶段主要检查语法错误（如漏写分号）。
- **链接**：将多个独立的目标文件组合成一个可执行文件（`.exe`），并解析它们之间的符号引用（函数、变量）。此阶段主要处理“找不到”或“重复”的问题 。

在 Visual Studio 中，`Ctrl + F7` 仅编译，`F5` 或生成项目则包含编译与链接。编译错误的错误码通常以 `C` 开头，链接错误的错误码以 `LNK` 开头 。

### 链接器的核心任务

链接器主要负责两件事：
1.  **找到入口点**：程序必须有一个起点。默认是 `main` 函数。即使代码只有一行，没有 `main` 也会导致链接失败 。
2.  **解析符号**：确保每一个被调用的函数或使用的外部变量，都能在某个目标文件或库中找到确切的定义 。

### 常见链接错误与解决

#### 1. 未解析的外部符号 (LNK2019)
- **现象**：链接器找不到某个函数的定义。
- **典型原因**：
    - 函数只有声明（如在头文件中写了 `void Log(...);`），但没有在任何 `.cpp` 中写实现。
    - 函数名拼写错误（定义时写成了 `Multipl`，调用时写的是 `Multiply`）。
    - 忘记将包含定义的 `.cpp` 文件加入项目编译。
- **解决**：提供该函数的完整定义；修正拼写；确保源文件参与构建 。

#### 2. 重复定义 / 多重符号 (LNK2005 / LNK1169)
- **现象**：链接器发现同一个函数（或变量）被定义了多次，不知道用哪个。
- **典型原因**：
    - **在头文件中直接写了函数体（定义）**。当多个 `.cpp` 文件都 `#include` 该头文件时，该函数就被复制进了多个目标文件，导致重复。`#include` 的本质是文本替换。
    - 在同一个项目里写了两个名字和参数完全相同的函数。
- **解决**：
    - **最佳实践**：头文件只放**声明**，定义统一放在一个 `.cpp` 文件中。
    - 如果必须在头文件里实现，对于短小函数可使用 `inline` 关键字，或者使用 `static` 使函数仅在当前翻译单元内可见 。

### 关键要点总结

- **链接是组合与解析**：把散落的 `.obj` 拼成程序，并把“调用”和“实现”连起来。
- **区分阶段**：遇到 `C` 错误去查语法；遇到 `LNK` 错误去查定义缺失或重复。
- **头文件纪律**：头文件用于“声明”接口，`.cpp` 文件用于“定义”实现。这是避免大多数链接错误的核心习惯。
