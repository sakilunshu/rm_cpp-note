这是 The Cherno《How C++ Works》的笔记整理。这一集是理解 C++ 构建流程的起点，核心在于建立“源文件 → 编译 → 链接 → 可执行文件”的整体认知，并区分预处理、编译、链接各自负责什么。

### 核心流程概览

C++ 程序从文本代码到可执行文件，大致经历三个阶段：

1.  **预处理**：处理以 `#` 开头的指令，主要是文本替换与文件包含。
2.  **编译**：将预处理后的源文件单独翻译为目标文件（`.obj` / `.o`）。
3.  **链接**：将多个目标文件合并，解析符号引用，最终生成可执行文件（`.exe`）。

### 预处理与 `#include`

`#include` 不是编译指令，而是**预处理指令**。它的作用很“粗暴”：找到指定的头文件，将其内容**原样复制粘贴**到当前 `.cpp` 文件中。这也是为什么头文件写得过大，会拖慢编译速度。

### 入口点：`main` 函数

每个 C++ 程序都需要一个入口点，默认是 `main` 函数。程序从这里开始逐行执行。`main` 是一个特例：即使声明为 `int`，也可以不写 `return`，编译器会默认返回 `0`。

### 编译与目标文件

**只有 `.cpp` 文件会被编译**，头文件不单独编译。每个 `.cpp` 文件被**独立编译**成一个目标文件（VS 中为 `.obj`）。这意味着编译器在处理一个文件时，**看不到**另一个文件中写了什么。

由此引出一个关键规则：如果你在一个文件中调用另一个文件里定义的函数，**必须在使用前提供声明**。声明告诉编译器“这个函数存在，参数和返回值长这样”，编译器就会放行；真正的函数体在哪里，是链接阶段的事。

### 声明与定义的区别

这是本集反复强调的一对概念：
- **声明**：承诺某个符号存在，给出名字和类型。例如 `void Log(const char* message);`。
- **定义**：提供实际实现。例如函数体 `{ std::cout << message; }`。

### 构建配置：Debug 与 Release

在 Visual Studio 中，解决方案配置通常有 Debug 和 Release 两种：
- **Debug**：关闭优化，便于调试，程序运行较慢。
- **Release**：开启优化（如 `/O2` 最大化速度），程序运行更快，但调试信息可能不完整。

解决方案平台（x86 / x64）则决定目标程序是 32 位还是 64 位。

### 关键要点总结

- `#include` 的本质是**文本复制**，发生在编译之前。
- 每个 `.cpp` **独立编译**，编译器不检查其他文件的内容。
- 跨文件调用函数，必须**先声明**，否则编译会报错（或链接时找不到定义）。
- 编译阶段处理语法与声明；链接阶段才真正把“调用”和“定义”连起来。
