这是 The Cherno《C++ Header Files》的笔记整理。这一集的核心在于：头文件本身不参与编译，它的唯一作用是**在预处理阶段被“复制粘贴”到 `.cpp` 文件中**，从而让编译器在编译当前文件时能看到必要的**声明**。

### 头文件的核心作用：声明而非定义

C++ 中，函数分为**声明**和**定义**两部分：
- **声明**：只告诉编译器“这个函数存在，参数和返回值长这样”，不需要函数体。
- **定义**：提供函数体的实际实现。

头文件的主要用途就是存放**声明**。当 `Main.cpp` 需要调用 `Log.cpp` 中定义的函数时，它不需要、也不应该直接包含 `Log.cpp`，而是包含 `Log.h`。`Log.h` 里只有声明，编译器看到声明后就放行；真正的函数体在哪，由链接器后续去解析。

### `#pragma once` 与头文件保护

这是本集最实用的技术点。如果同一个头文件在一个 `.cpp` 中被间接包含多次（例如 `A.h` 包含了 `Log.h`，`B.h` 也包含了 `Log.h`，而 `Main.cpp` 同时包含了 `A.h` 和 `B.h`），就会导致 `Log.h` 的内容被复制多次，引发**重复定义错误**。

`#pragma once` 放在头文件顶部，告诉编译器：**这个文件在一个翻译单元中只包含一次**。它是现代编译器的标准做法，简洁高效。

传统做法是**头文件保护宏**（Include Guards）：
```cpp
#ifndef _LOG_H
#define _LOG_H
// 头文件内容
#endif
```
原理是：第一次包含时 `_LOG_H` 未定义，宏生效，内容被包含；第二次包含时 `_LOG_H` 已定义，整段内容被跳过。`#pragma once` 本质上实现了同样的效果，但写法更简单。

### `#include ""` 与 `#include <>` 的区别

- **`#include "..."`**：默认以**当前文件所在目录**为起点查找，找不到再搜索编译器的包含路径。适合包含项目自己的头文件。也支持相对路径，如 `#include "../Log.h"`。
- **`#include <...>`**：直接在**编译器的标准包含目录**中查找，不搜索相对路径。适合包含标准库头文件（如 `<iostream>`）或第三方库头文件。

### 标准库头文件的命名约定

C++ 标准库头文件通常**没有 `.h` 后缀**（如 `<iostream>`、`<vector>`），而 C 标准库头文件保留 `.h` 后缀（如 `<stdlib.h>`、`<stdio.h>`）。这是 C++ 标准委员会有意为之，用于区分 C++ 标准库与 C 标准库。

### 关键要点总结

- 头文件用于存放**声明**，让编译器在编译当前 `.cpp` 时知道函数/类的存在。
- `#include` 的本质是**文本复制**，发生在编译之前。
- 必须使用 `#pragma once`（推荐）或头文件保护宏，防止同一翻译单元中重复包含。
- `""` 用于项目内头文件，`<>` 用于标准库/系统头文件。
- 头文件只放声明，定义放在 `.cpp` 中，是避免链接错误的基本纪律。
