
## 1. `&` 和 `*` 的双重含义，别混用

同一个符号，贴着类型写是**声明**，贴着变量写是**运算**。

| 写法 | 含义 | 类别 |
| :--- | :--- | :--- |
| `int& r = a;` | 声明引用 | 声明（贴类型） |
| `&a` | 取地址 | 运算（贴变量） |
| `int* p = &a;` | 声明指针 | 声明（贴类型） |
| `*p = 10;` | 解引用 | 运算（贴变量） |

**易错**：看到 `int* p = &a;` 里有 `*` 又有 `&`，以为两个都在运算。实际上第一个 `*` 是声明指针，第二个 `&` 才是取地址。

**口诀**：贴着类型走是声明，贴着变量走是运算。

---

## 2. 指针不是 `int`，只是“存了个地址数值”

- 指针底层存的内容确实是一个地址数值，可以被看作整数。
- 但指针的**类型是 `T*`，不是 `int`**，不能把 `int*` 直接赋给 `int`。
- `int*`、`double*`、`void*` 是**互不相同的类型**，不是“都是整数型”。

**易错**：因为“指针 = 整数”这句话，误以为所有指针都是同一种类型、可以随意互转。实际上只有 `void*` 能和具体类型指针隐式互转，其他类型之间必须显式强转，且强转后解引用可能读错数据。

---

## 3. 类型不影响指针存什么，只影响“怎么用地址”

类型的作用全部在**使用层面**：

| 影响 | 说明 |
| :--- | :--- |
| 解引用读写几个字节 | `int*` 读 4 字节，`char*` 读 1 字节 |
| 指针算术的步长 | `int*` 加 1 前进 4 字节，`char*` 加 1 前进 1 字节 |
| 能否直接解引用 | `void*` 不能直接 `*p`，必须先转类型 |
| 类型转换限制 | 不同类型指针不能隐式互转 |

**不影响**：指针变量本身的大小（x64 下都是 8 字节），也不影响它存的地址数值。

**易错**：以为 `int*` 和 `char*` 存同一个地址时“内容不同”。内容完全一样，只是解释方式不同。

---

## 4. 指针能改指向，引用不能改绑

这是指针和引用最本质的区别，也是最容易记反的地方。

```cpp
int a = 1, b = 2;
int* p = &a;
p = &b;        // 指针改指向：p 现在指向 b，合法

int& ref = a;
ref = b;       // 这不是改绑！这是把 b 的值赋给 a
               // ref 仍然是 a 的别名，a 变成 2
```

**易错**：把 `ref = b` 理解成“让引用改绑到 b”。引用**绑定后终身不变**，这行代码只是普通赋值。

**对照**：需要“重新指向”或“可能为空”时用指针；否则优先用引用。

---

## 5. 声明指针 ≠ 可以使用指针

```cpp
int* p;        // 声明了，但 p 里是垃圾地址
*p = 10;       // 危险！未定义行为
```

声明只是定义了类型，指针里还没有有效地址。必须让它指向一块有效内存后才能解引用：

```cpp
int a = 8;
int* p = &a;   // 现在 p 有效
*p = 10;       // 合法
```

**易错**：声明完指针直接解引用，或忘记初始化。

---

## 6. `void*` 能存不能直接解引用

```cpp
void* v = &a;
// *v = 10;        // 非法：编译器不知道读写几个字节
*(int*)v = 10;     // 合法：先转成 int* 再解引用
```

**易错**：以为 `void*` 是“万能指针”，什么都能直接操作。它只是“通用地址容器”，用之前必须转回具体类型。

---

## 7. 函数传参：按值传递改不了原变量

```cpp
void Increment(int value) { value++; }   // 副本，原变量不变
void Increment(int& value) { value++; }  // 引用，原变量被改
void Increment(int* value) { (*value)++; } // 指针，也能改，但写法更绕
```

**易错**：以为传指针或传引用“自动就能改原变量”。指针必须解引用 `*value` 才改到原变量；引用则直接写变量名即可。这也是 `scanf("%d", &a)` 必须加 `&` 的原因——它要地址才能写回原变量。

---

## 8. `new` 必须配 `delete`，数组要用 `delete[]`

```cpp
int* p = new int(8);
delete p;              // 单个对象

int* arr = new int[100];
delete[] arr;          // 数组必须用 delete[]
```

**易错**：
- `new` 了不 `delete` → 内存泄漏。
- 数组用 `delete` 而不是 `delete[]` → 未定义行为。
- 对同一块内存 `delete` 两次 → 未定义行为。

**降低风险的默认写法**：能用 `std::vector` 就不用 `new[]`，能用 `std::unique_ptr` 就不用裸 `new`。

---

## 9. 指针算术不是“加 1 字节”

```cpp
int* p;
p + 1;   // 前进 sizeof(int) = 4 字节，不是 1 字节
```

**易错**：以为 `p + 1` 就是地址数值加 1。实际步长由所指类型的大小决定。用 `char*` 去遍历 `int` 数组会错位，就是因为步长不对。

---

## 10. 小项目也别养成坏习惯

内存泄漏在小项目里可能“感觉不到”（进程结束系统回收），但**习惯会带进大项目**。决定风险的不是项目大小，是程序寿命、泄漏频率和数据规模。从现在起把“能用容器和智能指针就不用裸 `new`”当默认写法，成本很低。

## 一句话总纲

**指针 = 一个存地址的独立变量，能改指向、能为空；类型是操作说明书，不改变它存的是地址这个事实。`&` 取地址，`*` 按地址访问；贴着类型是声明，贴着变量是运算。**
除了按值传递（pass by value），C++ 里主要的传参方式还有**按引用传递**和**按指针传递**。它们解决的核心问题是同一个：**函数能不能修改调用者的原变量，以及要不要付出拷贝的代价**。

### 按值传递（Pass by Value）

函数拿到的是实参的一份**副本**，改副本不影响原变量。

```cpp
void f(int x) { x = 10; }   // 原变量不变
```

代价：如果传的是大对象（如 `std::string`、大结构体），会发生一次完整拷贝，有性能开销。

### 按引用传递（Pass by Reference）

函数拿到的是原变量的**别名**，操作引用就是操作原变量，没有拷贝。

```cpp
void f(int& x) { x = 10; }   // 原变量被改
```

如果不想让函数修改原变量，但也不想拷贝，用**常量引用**：

```cpp
void f(const int& x) { /* 只能读，不能改 */ }
```

这是传大对象时最常用的写法：避免拷贝，同时保证函数内部不改原值。

### 按指针传递（Pass by Pointer）

函数拿到的是原变量的**地址**，通过解引用可以修改原变量。

```cpp
void f(int* x) { *x = 10; }   // 原变量被改
f(&a);                        // 调用时传地址
```

它和引用传递效果类似，但写法更绕（要解引用、调用时要取地址）。指针传递的独特之处是**可以传 `nullptr`**，表示“没有对象”，引用做不到这一点。

### 三者对比

| 方式 | 能否改原变量 | 有无拷贝 | 能否为空 | 典型写法 |
| :--- | :--- | :--- | :--- | :--- |
| 按值 `int x` | 不能 | 有 | 不适用 | `f(a)` |
| 按引用 `int& x` | 能 | 无 | 不能 | `f(a)` |
| 常量引用 `const int& x` | 不能 | 无 | 不能 | `f(a)` |
| 按指针 `int* x` | 能（需解引用） | 无（只拷地址） | 能 | `f(&a)` |

### 怎么选

- **小类型（`int`、`char`、指针本身）**：直接按值传，简单。
- **大对象且函数不需要改**：用 `const T&`，避免拷贝。
- **需要修改原变量**：用 `T&`。
- **“没有对象”是合法状态**：用指针 `T*`，可以传 `nullptr`。
- **需要重新指向别的对象**：用指针，因为引用不能改绑。

### 补充：按值传递的“移动”

C++11 之后还有**移动语义**（`T&&`），它也是按值传递的一种变体，但用于“把资源从临时对象转移走”而不是拷贝。这属于进阶内容，初学阶段先掌握上面四种即可。
