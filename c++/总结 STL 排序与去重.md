### 一、 关于题目本身的逻辑（STL 的运用）
1. **数据存储**：用 `vector<int> v` 存所有输入的数字，因为要保留原来的顺序（虽然最后要排序，但在修改前它是原序）。
2. **排序**：用 `<algorithm>` 里的 `sort(v.begin(), v.end())` 对 `vector` 升序排列。
3. **去重**：用 `set<int> s`，把数据丢进去，它自带**自动排序**和**去重**功能。遍历 `set` 直接得到去重后的结果。

### 二、 代码执行与输入输出的“坑”

#### 1. `cin >> n` 的本质
* **它不是“获取变量”，而是“向用户要数据”**。
* 代码里写几次 `cin >> x`，程序就会停下来等你输入几次。
* **你的踩坑点**：你写了 `cin >> n;`，下面又写了 `if(!(cin>>n))`，导致程序向你要了**两次**数据。所以你输入两个 5 才放行。
* **正确做法**：只需要保留一个。防御性写法 `if (!(cin >> n)) return 0;` 本身没问题，但不要再额外多写一个 `cin >> n;`。

#### 2. 测试用例怎么给？
* 题目通常要求：先输入一个数 \(n\)（代表总个数），再输入这 \(n\) 个具体的数据。
* **你的踩坑点**：你输入了 `5 3 1 2 1`。
  * 程序把开头的 `5` 当成了 \(n\)。
  * 然后它要循环 5 次找数字，但后面只剩 `3 1 2 1` 这 4 个数。不够，所以它卡住了。
  * 你按了 `Ctrl + Z`（`^Z`），强行结束了输入，导致程序抓取了错误的数据，最后输出少了 `5`。
* **正确做法**：要测试这串数据，必须输入 **`5 5 3 1 2 1`**，把第一个 5 作为个数，后面的才是内容。

#### 3. `Ctrl + Z` 是干嘛的？
* 它是“输入结束符”。当你在终端里测试时，如果程序死等输入（比如你不想再敲数字了），可以按 `Ctrl + Z` 然后回车，程序就会认为“没数据了”，从而继续往下走（或者直接崩溃）。

### 三、 提交作业 / 考试系统的红线 🚨

这一点极其重要，关乎你能不能拿分！

1. **千万不要输出多余的提示语**。
   * 你自己测试时写 `cout << "数据个数：" << endl;` 或 `cout << "请输入数据：" << endl;` 完全没问题。
   * **但是交卷前，必须把这些全部删掉！** OJ 系统是机器死板比对输出的，如果你多打了一个汉字、一个空格，都会直接报 `Wrong Answer (WA)` 或 `Presentation Error (PE)`。
2. **标点符号的中英文**。
   * 题目要求输出的 `排序输出: ` 里面的冒号是**英文半角冒号 `:`**。
   * 你代码里写的是中文全角冒号 `：`，交上去绝对过不了，必须改过来。
3. **行末空格问题**。
   * 严格的系统不允许最后一个数字后面多一个空格。用 `bool first = true;` 的技巧可以完美规避这个问题。
