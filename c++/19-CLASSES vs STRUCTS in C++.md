这是 The Cherno《CLASSES vs STRUCTS in C++》的笔记整理。这一集的核心结论非常干脆：**在 C++ 中，`class` 和 `struct` 在技术上几乎完全一样，唯一的实质区别是默认访问权限**。选择用哪个，更多是约定俗成的语义习惯，而非语言强制。

### 唯一的实质性区别：默认访问权限

这是 C++ 标准明确规定的差异，也是 Cherno 整集反复强调的一点：

- **`class`**：成员默认是 **`private`**。不写 `public:` 的话，外部无法访问。
- **`struct`**：成员默认是 **`public`**。不写访问修饰符，外部也可以直接访问。

```cpp
class Player {
    int x, y;   // 默认 private，外部访问会报错
};

struct Vec2 {
    float x, y; // 默认 public，外部可以直接 vec.x 访问
};
```

除此之外，两者在能力上完全对等：都可以有方法、构造函数、继承、静态成员，等等。

### 为什么 C++ 还保留 `struct`：为了兼容 C

`struct` 不是 C++ 的“二等公民”，它存在的历史原因很直接：**C 语言有 `struct`，没有 `class`**。C++ 为了能直接编译 C 代码、与 C 保持兼容，保留了 `struct` 关键字。

所以你在 C++ 里写 `struct`，编译器并不会把它当成“弱化版的类”来处理，它就是一个默认公开的类。

### 使用习惯：什么时候用哪个

既然技术上没区别，实际写代码时怎么选？Cherno 给出的建议是**语义导向**，而非技术约束：

**用 `struct` 的场景**：只用来把几个相关变量打包在一起，没什么复杂逻辑。也就是常说的 **POD（Plain Old Data）** 类型。比如数学向量、颜色值、坐标点：
```cpp
struct Vec2 {
    float x, y;
    void Add(const Vec2& other) {
        x += other.x;
        y += other.y;
    }
};
```
这里放一个简单的 `Add` 方法也没问题，但整体定位是“数据容器”。

**用 `class` 的场景**：对象有较多功能、需要封装、可能涉及继承。比如游戏里的 `Player`、`GameWorld` 这类有明确行为和状态管理的类型。

### 关键要点总结

- **技术区别只有一个**：默认访问权限，`class` 私有，`struct` 公开。
- **`struct` 为兼容 C 而存在**，不是被淘汰的旧语法。
- **选哪个看意图**：数据打包用 `struct`，有行为的对象用 `class`。
- **不要混用习惯**：不要用 `struct` 去做复杂的继承体系，也不要给纯数据包强行套一个 `class` 再加一堆 `public:`。保持代码的语义一致性，比纠结关键字本身更重要。
