这是 The Cherno《Destructors in C++》的笔记整理。这一集讲的是构造函数的“邪恶双胞胎”：析构函数。核心观点是：**析构函数在对象被销毁时自动调用，专门用来清理对象占用的资源，防止内存泄漏**。

### 析构函数是什么：构造的反面

构造函数在对象**创建**时运行，负责初始化；析构函数在对象**销毁**时运行，负责清理。它的写法是在类名前加一个波浪号 `~`，没有返回值，也不接收参数：

```cpp
class Entity {
public:
    Entity() {  // 构造函数
        std::cout << "Created!" << std::endl;
    }
    ~Entity() { // 析构函数
        std::cout << "Destroyed!" << std::endl;
    }
};
```

### 什么时候被调用：取决于对象在哪

这是本集的一个关键细节。析构函数的调用时机取决于对象分配在**栈**上还是**堆**上：

**栈对象**：离开作用域时自动调用。
```cpp
void Function() {
    Entity e;   // 构造
}               // 离开作用域，自动析构
```

**堆对象**：必须手动 `delete` 才会调用。如果 `new` 了却不 `delete`，析构函数永远不会运行，那块内存就泄漏了。
```cpp
Entity* e = new Entity();
delete e;       // 这时才析构
```

### 为什么需要它：清理资源

构造函数里如果申请了资源（堆内存、文件句柄、网络连接等），就必须在析构函数里释放。这是 C++ 中 RAII（资源获取即初始化）思想的基础：**资源在构造时获取，在析构时释放**，利用栈对象离开作用域自动销毁的特性，保证资源一定会被清理，不会因为忘记 `delete` 而泄漏。

### 一个容易踩的坑：手动调用析构函数

Cherno 提到，析构函数**可以**被手动调用，但**极不推荐**。手动调用 `e.~Entity()` 只是执行了析构函数体，并不会释放对象占用的内存。如果之后再自动析构一次，就可能出问题。日常编码中，让析构函数自动触发即可。

### 关键要点总结

- **析构函数 = `~类名()`**，对象销毁时自动调用，用于清理资源。
- **栈对象离开作用域自动析构；堆对象必须 `delete` 才析构**。
- **构造函数里申请了什么，析构函数里就释放什么**，这是避免内存泄漏的基本纪律。
- **不要手动调用析构函数**，交给语言机制自动处理。
