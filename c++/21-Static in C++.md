这是 The Cherno《Static in C++》的笔记整理。这一集的核心在于：`static` 在 C++ 中**根据使用位置的不同，含义完全不一样**。Cherno 明确区分了两种主要场景：类或结构体**外部**的 `static`，以及类或结构体**内部**的 `static`。

### 类/结构体外部的 `static`：改变链接可见性

当 `static` 用在全局变量或全局函数上时，它的作用是**把符号的链接属性改为内部链接（internal linkage）**。这意味着这个变量或函数**只对定义它的那个翻译单元（`.cpp` 文件）可见**，其他文件看不到它。

**为什么需要它**：默认情况下，全局变量是外部链接的，所有文件都能访问。如果你在两个 `.cpp` 里都定义了 `int s_Variable = 5;`，链接器会报“重复定义”错误。加上 `static` 后，每个文件都可以有自己的同名私有变量，互不冲突。

```cpp
// A.cpp
static int s_Variable = 5;  // 仅 A.cpp 可见

// Main.cpp
int s_Variable = 10;        // 不冲突，链接通过
```

Cherno 的建议是：**除非你确实需要跨翻译单元链接，否则应该把全局变量和函数标记为 `static`**。这相当于给它们加了一层“文件私有”的保护，能有效避免大型项目中的命名冲突。

注意：另一个文件不能用 `extern` 来访问被 `static` 修饰的变量，因为链接器根本找不到它。

### 类/结构体内部的 `static`：改变归属

当 `static` 用在类或结构体内部时，含义发生了变化：**这个变量或函数属于类本身，而不是类的某个实例**。

**静态变量**：无论你创建多少个类的对象，静态成员变量**只有一个实例**，所有对象共享同一块内存。任何一个对象修改了它，其他对象看到的都是修改后的值。

```cpp
struct Entity {
    static int x;  // 所有 Entity 对象共享这一个 x
};
int Entity::x;     // 必须在类外定义（分配内存）

Entity e1, e2;
e1.x = 5;
// e2.x 现在也是 5
```

这里有一个容易忽略的细节：静态成员变量在类内只是**声明**，必须在类外进行**定义**（如 `int Entity::x;`），否则链接会报错。

**静态方法**：静态方法同样属于类，不属于实例。它**没有 `this` 指针**，因此**不能访问类的非静态成员变量或非静态方法**。它只能操作静态成员。

调用静态方法不需要创建对象，可以直接用 `类名::方法名()` 调用。

### 补充：局部 `static`（函数内部的静态变量）

虽然本集主线是前两种，但 Cherno 在系列中另外讲了局部 `static`。它的作用是：**变量的作用域仍然局限在函数内，但生命周期延长到整个程序运行期间**。函数第一次执行到该声明时初始化，之后每次调用函数，它都保留上一次的值。常见的用途是实现单例模式。

### 关键要点总结

- **类外 `static`**：把全局符号变成“文件私有”，避免链接冲突。**推荐默认使用**。
- **类内 `static` 变量**：全类共享一份，修改对所有实例可见；必须在类外定义。
- **类内 `static` 方法**：属于类，无 `this`，不能访问非静态成员。
- **一句话记法**：类外 `static` 管的是“谁能看到我”，类内 `static` 管的是“我属于谁”。
