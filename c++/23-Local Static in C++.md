这是 The Cherno《Local Static in C++》的笔记整理。这是 `static` 系列的第三集，讲的是它用在**函数内部局部变量**上的含义：变量仍然只有函数能访问，但它的**生命周期被延长到了整个程序运行期间**。

### 核心效果：作用域不变，寿命变长

普通的局部变量在函数每次被调用时都会**重新创建**，函数一返回就**销毁**。加上 `static` 后，变化在于：

*   **作用域**：不变，仍然只在函数内部可见，外部无法访问。
*   **生命周期**：从“函数调用期间”延长为“整个程序运行期间”。它只在**第一次执行到声明语句时初始化一次**，之后每次调用函数，它都保留着上一次的值。

```cpp
void Function() {
    static int i = 0;  // 第一次调用时初始化为 0，之后不再初始化
    i++;
    std::cout << i << std::endl;
}
// 连续调用三次，输出：1 2 3
```

如果去掉 `static`，每次调用都会重新创建 `i` 并初始化为 0，输出永远是 1。

### 和“全局变量”的区别

局部静态变量的效果类似于在函数外定义一个全局变量，但有一个关键优势：**全局变量任何地方都能改，局部静态变量只有这个函数能碰**。这既保留了“值能跨调用累积”的能力，又把访问权限锁死在了函数内部，避免外部误改。

### 典型用途：单例模式（Singleton）

Cherno 举的一个实际例子是单例：确保一个类全局只有一个实例。用局部静态变量可以很简洁地实现：

```cpp
class Singleton {
public:
    static Singleton& Get() {
        static Singleton instance;  // 第一次调用 Get 时构造，之后一直存在
        return instance;
    }
};
```

如果不加 `static`，`instance` 在 `Get()` 返回后就被销毁了，返回的引用会指向一块已经失效的内存。加了 `static`，`instance` 的生命周期覆盖整个程序，引用始终有效。

### 一个需要留意的点

Cherno 及笔记整理者也提到，局部静态变量**在日常编码中并不被鼓励大量使用**。因为它引入了“隐藏状态”：函数的行为不再只由参数决定，还依赖它被调用的历史。这会让代码更难理解和测试。单例这类需要“全局唯一且延迟初始化”的场景，是它比较合理的用武之地。

### 关键要点总结

*   **局部 `static` = 作用域限定在函数内 + 生命周期覆盖整个程序**。
*   **只初始化一次**，后续调用保留上一次的值。
*   **比全局变量安全**：外部无法访问，避免误改。
*   **典型场景**：单例模式中确保实例存活到程序结束。
*   **不宜滥用**：隐藏状态会让函数行为变得难以预测。
